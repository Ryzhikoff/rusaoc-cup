# Rusaoc Cup

Статический сайт со статистикой Age of Empires II: поиск игроков, сортировка, карточки выступлений и флаги стран.

- `site/index.html` — выбор версии.
- `site/rusaoc-cup-statistics.html` — Google Таблица организаторов с дополнениями GoodGame для пустых турниров; страны из Liquipedia.
- `site/rusaoc-cup-liquipedia.html` — участники, результаты сеток и победители по страницам Liquipedia.

Версия Liquipedia остаётся отдельной: её результаты не добавляются в основную таблицу. Переходов между страницами статистики нет; обе доступны с начальной страницы. Страны берутся из профиля игрока, а при его отсутствии — из последних явных указаний на страницах турниров. Неизвестные страны не угадываются.

## Дополнения GoodGame

При каждом обновлении сначала загружается исходная Google Таблица. Если у турнира есть хотя бы одна строка результатов в ней, весь турнир берётся только из неё. Для полностью пустых колонок и новых завершённых выпусков используются публичные сетки GoodGame. Вчерашние дополнения не складываются с новым срезом: появление данных организатора полностью заменяет дополнение без дублирования. Источник каждого выступления виден в карточке игрока; список дополненных турниров — над рейтингом.

GoodGame загружается через JSON/GraphQL, используемый самим сайтом, без аккаунта или секретов. Импортируются завершённые Rusaoc Cup по Age of Empires II организатора `mr_moon`. Сейчас поддерживается одна полная сетка Double Elimination для 1v1, 2v2 и 3v3. Несыгранные проходы и отмеченные технические результаты исключаются из побед, поражений и сыгранных матчей. Участие определяется попаданием в сетку, а не одной регистрацией. Серия 2:0 — один выигранный матч; версия Liquipedia по-прежнему считает карты.

В командных турнирах GoodGame может содержать только капитанов. Составы берутся из явно указанных пар/троек Liquipedia; проверенные дополнения и соответствия ников находятся в `data/goodgame-identities.json`, с пояснением и ссылками на источники. Результаты матчей при этом берутся только из GoodGame. Найденные публичные ID аккаунтов сохраняются в срезе для последующих обновлений. Нечёткое сравнение ников и распределение игроков по предполагаемому рейтингу не используются.

В исходной Google Таблице призовые места заданы общей суммой, без привязки к турнирам. Поэтому места GoodGame показаны отдельно, включая место в каждом дополненном турнире, и не прибавляются к сводным титулам Google. Это исключает двойной учёт при частичном обновлении сводки организатором.

Неизвестный формат, неполная сетка или неоднозначный состав оставляют новый турнир в списке ожидающих проверки. Ошибка сети/API или исчезновение ранее опубликованного дополнения останавливают обновление; предыдущий сайт сохраняется. Новые 3v3 не считаются готовыми, пока не известны все составы.

## GitHub Pages

Репозиторий должен быть публичным для использования GitHub Pages на GitHub Free.

1. В **Settings → Pages → Build and deployment → Source** выбрать **GitHub Actions**.
2. В **Actions → Update and publish statistics → Run workflow** запустить публикацию. Для публикации уже сохранённых данных снять `Download fresh statistics before publishing`.
3. Адрес сайта: <https://ryzhikoff.github.io/rusaoc-cup/>.

Workflow запускается при изменениях `main`, вручную и ежедневно в **00:00 по Гринвичу (UTC)** (`0 0 * * *`, UTC). Запуск GitHub может задерживаться. Обновление по расписанию загружает все источники, проверяет данные, сохраняет HTML коммитом и публикует каталог `site/`.

При загрузке или проверке с ошибкой новый сайт не публикуется. Посетителям остаётся доступен предыдущий срез. Публичные страницы не обращаются к API, не сохраняют статистику в браузере и не содержат кнопки обновления.

Автоматические коммиты обновляют историю репозитория; расписания публичных репозиториев GitHub отключаются после 60 дней без активности. При длительных сбоях обновления следует проверить вкладку Actions. `GITHUB_TOKEN` создаётся GitHub для каждого запуска; отдельные секреты для публикации и публичных источников не нужны. Политики организации или защита ветки могут запретить автоматический коммит — workflow должен иметь право записи в `main`.

## Локальная работа

Нужен Python 3.10 или новее, сторонних зависимостей нет. Workflow использует Python 3.13.

```sh
python3 -m unittest discover -s tests -v
python3 scripts/update.py
python3 scripts/check_site.py
python3 -m http.server 8000 --directory site
```

Открыть <http://localhost:8000>. HTML также открывается прямо из файла.

`scripts/update.py` получает Google Таблицу, архив Liquipedia, дополнения GoodGame и страны игроков. Оба HTML заменяются только после получения и проверки всех данных. Новые события и игроки включаются автоматически, если структура источников осталась прежней. Резкое сокращение архива или числа игроков, несовпадающие итоги таблицы и неполные API-ответы останавливают обновление.
